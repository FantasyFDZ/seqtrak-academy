# 设计方向

2026-11-10 和用户一起定的。背景：用户看过全部页面后提出“达到产品级的水准；要有趣，动效要丰富，现代”。
我先做了一版只加动效、长相不大改的样稿，用户说“想更大胆”；又做了三套更大胆的长相让他选，他的选择如下。

定方向的时候有一份可以点的样稿 `public/design-lab.html`，是这份文档“看得见的版本”。四期做完之后，2026-11-10 用户说删掉，已经删了：它里面的样子都搬进了正式页面。下文里的“样稿第 02 块”“样稿里的 `SND`”这些说法指的就是它，现在一律以正式页面和代码为准（音效在 `sfx.js`，气泡在 `lesson.js`，结算在 `game.js`，教练的脸在 `coach-face.js`）。

## 用户定下来的三件事

1. **配色：保留“机身”和“霓虹”两套，可以切换。**
   - 机身 = 现在的浅色：浅灰底、桔红加机身灰、键帽、丝印。
   - 霓虹 = 深色：近黑的底、发光的桔红 / 青 / 黄，像夜里的舞台。
   - 他**没有选**“A 色块”（粗黑线、硬阴影、整块纯色）和“B 游乐场”（圆润卡通、紫色主调）。不要往这两个方向走。
   - 默认用**机身**（用户 2026-11-10 确认）。顶栏和设置里可以切到霓虹，记住上次的选择。
2. **玩法：四样全要。** 闯关地图、教练当主角、等级和徽章、更夸张的庆祝。
3. **动效和界面音效：默认全开。** 设置里可以分别调低或关掉，并且尊重系统的“减少动效”。

所以“更大胆”落在**玩法和动效**上，长相是在现有的硬件感上做两套配色，不是换一种视觉语言。

## 三条主线

- **节拍感**：界面里“活着的东西”跟着 BPM 呼吸——标志的四根条、地图上当前这一关、音游舞台的光、教练。
- **手感**：每次按下都有行程（键帽往下走）、有一声轻响、有回应。
- **进度感**：学完一关点亮一关；经验值、等级、连续天数、徽章随时看得见。

## 底座

- **颜色全部走 CSS 变量**，两套配色只是两组变量值（参考样稿里 `body[data-skin="neon"]` 那一段）。新写的样式里不许出现写死的颜色。
- **真机面板的图（`device-panel.js` 的 SVG）不跟配色变**：它画的是实物，灰色机身加桔红右区，两套配色下都一样。霓虹配色下给它一个浅色的“台面”衬着。
- **音游画布**（`game.js` 用 `INK()` 之类的函数取色）要跟配色变。
- 缓动两条：`--out`（平滑收尾，用于状态变化）、`--pop`（带过冲，用于奖励和出现）。时长三档：约 80 ms（按下）、240 ms（状态变化）、420 ms（出现 / 庆祝的单个元素）。
- 循环动效只放在“活着的东西”上，周期用 `--beat`（= 60 秒 ÷ BPM；没连真机时按 120）。
- **动效两档**：丰富（默认）/ 克制。克制 = 去掉循环动效和粒子，保留状态变化。系统开了“减少动效”时按克制处理。
- **界面音效**：全部用 Web Audio 现场合成，不带音频文件（写法见样稿里的 `SND`）。音量明显低于机器和音游的声音。**音游打着的时候不放界面音效**，免得干扰判定。
- 最小字号 12 px。现在大量 10–11 px 的等宽小标签要放大。

## 平板横屏（用户 2026-11-10 追加的要求）

用户打算以后把它移植成平板上的 app，要求**每一页都按平板横屏来设计**。现在它仍然跑在 Mac 的 Chrome 里，所以做法是：以平板横屏为基准画布，桌面浏览器是它的放大版。

- **目标是 iPad**（用户 2026-11-10 确认），所以按 4:3 的横屏做基准。
- **基准尺寸**：最小 1024 × 768，必须完整可用；主要按 1180 × 820 设计；大到 1366 × 1024 不显得空。桌面上窗口更宽时，内容区居中，不无限拉宽。
- **导航放到左边**：横屏最缺的是高度，顶栏正好占着它。改成左侧一条窄的导航栏（图标加字），连接状态和教练的入口也放在这条栏上。
- **要动手的页面一屏放下**：动手步骤、编程挑战、音游、真机镜像、导览，在 1024 × 768 下不用滚动就能同时看到“要操作的东西”和“现在做什么”。做法是左右分栏：左边主区（面板 / 舞台），右边一栏（当前指令、教练、状态）。讲解和列表这类页面可以上下滚动，但只滚内容区，导航和“下一步”始终留在屏幕上。
- **像 app，不像网页**：整页不出现整体滚动和橡皮筋回弹（主体用固定的视口高度，内部区域各自滚动）；留出安全区（`env(safe-area-inset-*)`）；屏幕键盘弹出时（向教练提问）输入框不被挡住，布局不被顶乱。
- **给手指用，不是给鼠标**：
  - 能点的东西至少 44 × 44 像素，彼此留出间距。面板图上的小键在要操作的场合必须够大：放大面板，或者只放大当前相关的那一块。
  - 任何信息都不能只在鼠标悬停时出现。悬停效果可以有，但要有点按或常显的替代（比如地图节点的课名）。
  - 不依赖键盘。Enter、空格这类快捷键只是加分项。
  - 拖动和长按用指针事件做，处理好和系统长按菜单、文字选择、页面滚动的冲突（`touch-action`、禁止选中）。
- **只做横屏**：竖着拿的时候给一句“请把平板横过来”，不单独设计竖屏。
- **要顺**：动效在平板上也得流畅，避免大面积模糊和大块阴影的连续动画。
- **检查**：每一期都在 1024 × 768、1180 × 820、1366 × 1024 三个尺寸、两套配色下截图检查（给 `tools/shots.sh` 加上尺寸参数）。

### 移植时界面以外的两件事（现在不做，记在这里）

把界面按平板横屏做好，解决的只是“界面”这一块。真要变成平板 app，还有两块要换：

- **连接机器的方式**：现在靠浏览器的 Web MIDI。就我所知，iPad 上的浏览器内核不提供 Web MIDI，做成 app 时要用系统原生的 MIDI 接口来桥接；安卓平板的 Chrome 有 Web MIDI。**这一条移植前要重新核实。** 所以要一直守住现在的边界：和机器打交道的代码只在 `public/js/midi.js` 一处，别的模块不直接碰浏览器的 MIDI 接口。
- **本地服务**：进度存储和 AI 的转发现在由电脑上的 Node 服务做，平板上没有它。同样守住“页面只通过 `public/js/api.js` 找服务”这一条，移植时换掉它后面的实现。

## 玩法

### 闯关地图（路线图）

- 一章是一个区域，一节课是一个关卡节点，沿一条弯弯的路排开。
- 节点三种状态：通关了（显示拿了几颗星）、现在这一关（跟着节拍跳）、还没解锁。
- 每章最后一关是“章节挑战”，画得大一号。**先不新增课程内容**：用每章现有的最后一节课来当。
- 最上面是“接着练”：一眼看到下一关是什么，一键进去。旁边是等级、连续天数、本周目标。
- “制作中”的章节（第 4–8 章）画成远处还没开放的区域，不要再用虚线框。

### 等级和徽章

- **经验值**：只按现有数据能算出来的事给。完成一个课程步骤、完成一节课（星越多越多）、打完一局音游（按准确率）、每天第一次练习、连续天数的加成。具体数值由实现的人定，原则是：认真练一次（半小时）大约升一级的前几级，后面逐级变慢。
- **等级**要有名字（比如从“学徒”一路到能上台的称呼），不要只是数字。
- **徽章**首批 10–12 个，条件必须能从进度数据（`store` 里的 `lessons` / `charts` / `practiceDays` / 每局结果）判定。方向：第一次在真机上出声、编出第一个四踩、第一次全 PERFECT、连击到 16 / 50、连续练 3 / 7 / 30 天、听写题一次过、写出第一个自己的鼓点、“找按键”满分、学完一整章。
- 旧的进度文件里没有这些字段：读的时候要补缺省值，并且能**从已有进度回算**出经验值和已经达成的徽章。

#### 经验值、等级、徽章（第一期定稿，2026-11-10）

规则写在 `public/js/levels.js`（纯函数，Node 里也能跑），改规则要同时改这一节。`node tools/xp-check.mjs [数据目录]` 可以拿一份进度文件算一遍看结果（只读）。

**经验值**。大部分是从进度“算出来的”，不是另外记的账，所以旧进度文件不用迁移、也不会重复给：

| 做了什么 | 给多少 | 从哪算 |
|---|---|---|
| 课程里走完一步 | 10 | `lessons[id]`：学完的课按全部步数算，没学完的按 `stepIndex` |
| 学完一节课 | 1 星 60 / 2 星 80 / 3 星 100 | `lessons[id].done / stars`（重学拿到更多星，补差额） |
| 学完小课堂的一关 | 1 星 20 / 2 星 25 / 3 星 30 | `classroom[id].done / stars`（重学拿到更多星，补差额；清单里已经没有的关不算） |
| 打完一局音游（看示范不算） | 2 + 准确率 × 10，也就是 2–12 | 每局结算时加到 `game.playXp` |
| 每天第一次练习 | 20 | `practiceDays` |
| 连续练习的加成 | 连续第 n 天再加 (n − 1) × 5，最多 25 | `practiceDays` |

小课堂那一行是 2026-11-10 接上的，数是做的人定的（用户没有确认过）。怎么定的：主线一节课连步骤带过关大约 150 经验、半小时，合每分钟 5 经验；小课堂一关三五分钟，取 20–30，三档的比例和课程一样（0.6 / 0.8 / 1 取整）。一关大约等于主线的两三步、音游满分打三局；连着学半小时（七关上下）大约 200，和“认真练一次”的量一样。现在开放的 12 关全拿三星是 360，32 关做完是 960，占满级 8500 的一成多一点，不会让等级表失衡。它也是“算出来的”，没有走下面那个记账的口子：这样学过的关不用补记，也不会重复给，清空进度时不会剩下对不上的账。

以上都不是的内容，用 `store.addXp(数量)` 加，记在 `game.extraXp` 里；这一种是记账，防重复由调用的一方负责。眼下没有人用，是给以后的新内容留的口子。

音游给得少是有意的：一局只有十几秒，给多了就成了刷分。按这套数，认真练一次（一节课加课里的几局音游）大约 200 经验。

**等级**（到这一级需要的总经验）：1 学徒 0 / 2 按键手 150 / 3 节拍手 400 / 4 鼓手 750 / 5 律动手 1200 / 6 贝斯手 1750 / 7 和弦手 2400 / 8 音色师 3200 / 9 采样师 4200 / 10 编曲人 5400 / 11 制作人 6800 / 12 现场演出者 8500。前两级大约练一次升一级，之后逐级变慢；学完现有的第 0–3 章大约到 8、9 级，后面五章做出来、全部学完差不多正好到顶。名字跟着课程走（鼓 → 贝斯 → 和弦 → 音色 → 采样 → 编曲 → 现场）。

**徽章**（首批 12 个，接上小课堂时加了 1 个，现在 13 个）。拿到之后不会收回（比如“连练 3 天”拿到之后断了，徽章还在）：

| 徽章 | 条件 | 判定用的数据 | 旧进度能回算吗 |
|---|---|---|---|
| 第一声 | 第一次在真机上出声：用 SEQTRAK 打完一局音游，或学完 0.2「让真机出声」 | `game.stats.midiPlays`、`lessons['0-2']` | 能（练习记录里每一局都记了是不是真机打的） |
| 四踩 | 编出第一个四踩：学完 1.2「16 个格子」 | `lessons['1-2']` | 能 |
| 一下不差 | 一局音游全是 PERFECT，一下没多按 | `game.stats.fullPerfect` | 能（练习记录） |
| 连击 16、连击 50 | 一局里连着打中 16 / 50 下 | `game.stats.maxCombo` | 能（练习记录） |
| 连练 3 天、7 天、30 天 | 连续这么多天都练了 | `practiceDays` 里最长的一段 | 能 |
| 金耳朵 | 听写题一次过：自己点“检查”没有失败过就过关 | `game.stats.dictationAce`（课程播放器在过关时记） | **不能**，从改版之后算起 |
| 原创 | 在“自由创作”里写出自己的节奏交给教练点评；学完 1.5 也算 | `game.stats.ownBeat`、`lessons['1-5']` | 学完 1.5 的能 |
| 指哪按哪 | “找按键”10 题全对 | `panelQuiz.best` | 能 |
| 通关一章 | 把任意一章的课全部学完 | `lessons` | 能 |
| 三线齐亮 | 小课堂的乐理、节奏、效果三条线，各学完一关 | `classroom`（每条线最早学完的那一关；徽章的时刻是最后凑齐的那一下） | 能 |

- 小课堂只加了“三线齐亮”这一个：它的形式用户还没确认，先放一个把三条线都带到的。“把开放的关全学完”这一类没有加，因为开放的关还会从 12 涨到 32，条件会跟着变；等 32 关做完再看。
- “连击 50”目前只有「流行基本鼓」（52 个音）这一个内置谱面够长，等于要求几乎全连；后面章节的谱面更长，到时候再看要不要调。
- 回算（`backfillGame`）：进度文件里没有 `game` 这一段时做一次。读得到练习记录（`data/sessions.jsonl`，最多最近 200 局）并且局数对得上，就逐局算经验、连击、全 PERFECT、是不是真机打的；否则每个谱面按“局数 × 最好那一局的经验”估，连击和全 PERFECT 只看得到最近一局。回算出来的等级不当成“升级”来庆祝；徽章会在首页标“新”，教练说一句“你之前练的我都记上了”。
- 进度文件里新增的字段：`settings.skin`（`body` 机身 / `neon` 霓虹）、`settings.motion`（`rich` / `calm`）、`settings.uiSound`；`game: { v, playXp, extraXp, stats, badges: { 徽章 id: 拿到的时刻 }, seen: { level, badges, intro } }`。`seen` 记的是已经给用户看过的等级和徽章。小课堂的进度在 `classroom: { 关的 id: { done, stars, at, times } }`（`views/classroom.js` 写的），经验和“三线齐亮”就是看它算的；`store.resetProgress()` 会把它一起清掉。
- 界面怎么知道：`store.on('xp' | 'levelup' | 'badge', …)`。第一期的做法是顶栏的等级条涨一下，整节课这样的大数出一条提示条，升级和徽章出提示条 + 彩带 + 一声；**全屏的庆祝留给第 3 期**。首页用 `store.progress()` 一次拿全（经验、等级、连续天数、本周、徽章）。

### 教练当主角

> **2026-11-13 改了：教练换成了一只小鸟“啾啾”**（红嘴相思鸟；样稿页 `public/bird-lab.html`，代码 `bird.js` / `bird-voice.js` / `jiu.js` / `coach.js`）。用户的要求：拟物化成一只代表音乐的鸟，用不同的叫声传递情绪，能在屏幕上飞来飞去指导按键的位置；体型小、颜色鲜艳、叫声好听；鸟是他自己挑的，名字也是他从候选里定的；点头和摇头要分得开（摇头用横着压扁的那一版，“在屏幕平面里转”的那版他看过说原来的好）；对话“前端要体现啾啾的特点，而不是传统的 coding agent”。定下来的做法：
> - 全应用只有一只。平时蹲在左边导航栏最下面的窝里；页面上给它留了位置（`coachFace()` 留一小截树枝：首页问候卡、音游结算卡、过关和升级的庆祝卡、小课堂）就飞过去；动手的步骤里飞到要按的键上方悬停着指；做偏了摇头，整步做完翻跟头；音游打着的时候不出声、在窝里跟着拍子点头；好久没动静打瞌睡。
> - 和它说话：点它（或窝）→“啾！怎么啦？”加上按场合挑的选项（页面用 `coach.offer()` 给），打字问排在最后。即时回答一句一句从它身边冒出来（点一下下一句），说到哪个键就飞过去；“这个键是干嘛的？”= 指哪讲哪（按键百科，不调 AI）；“写张小纸条”、点评、排计划写成一张小纸条，可以收进纸条本（同一天后来改成全都走即时引擎，几秒钟就有；小纸条只是写法不同，服务端 `format: 'note' | 'plan'`）。没有聊天记录那一栏，也不露引擎名字。
> - 它主动说的一句（`nudge()`）从它所在的地方冒出来，时机和下面写的一样。
> 下面这几条是旋钮脸那时候写的，留着做历史。

- 形象：用旋钮画的一张脸（样稿第 05 块）。要有几种神态：待机、在想、说话、高兴、给你打气。
- 它出现的时机：进首页打招呼并说今天练什么；一个步骤卡了一阵子没进展；连着打空好几下；做完一项、过了一关；升级、拿到徽章。
- 点它就能提问（接现有的 `coach.js`，即时引擎和深度引擎不变）。
- **音游打着的时候不出来说话。**

### 更夸张的庆祝

- 做完一项任务：小（一个勾、一小撮彩带、一声）。
- 过一节课：全屏。星星一颗一颗砸下来、经验条涨上去、有新徽章就亮出来、教练说一句。
- 音游连击到 8 / 16 / 32：舞台变色、震一下、连击数放大。
- 升级：全屏。
- 克制档下这些都缩成一次性的小反馈。

## 第 2 期做完之后的样子（2026-11-10）

**做了的**

- **舞台**（`game.js` 的 `RhythmGame`，样式在 `app.css` 的“音游”一段）。轨道排在舞台正中、尽量宽（手指要点得中），两边留出的空地左边放连击数、右边放四种判定各打了几个。舞台的光跟着节拍亮，每小节第一拍更亮。打中：那条轨道亮一道光柱，判定字从轨道上冒出来（PERFECT，或者“早 12”“晚 30”），丰富档再溅几片碎片；漏了：轨道闪一下红、冒一个 MISS；多按了冒一个“多了”。轨道底下那排键帽 44 像素高、有厚度、按下会沉，没接机器时点它就是打（几根手指一起点也行）；打着的时候手指在舞台上不会带着页面滚（`.game-stage.live` 的 `touch-action`）。
  - 分工：轨道、音符、光、碎片画在画布上；连击、计数、横幅、判定字是盖在画布上的普通元素，`game.js` 只管往上放、换 `data-heat`，长什么样、怎么动都在样式里。以后要调反馈的样子，改样式就行。
- **连击里程碑**：到 8 / 16 / 32，舞台边上亮一圈、连击数和判定线换一种颜色（`--heat-1` 桔红、`--heat-2` 黄、`--heat-3` 青，两套配色各有一组值），舞台正中出一条横幅（“×8 稳住了”“×16 火热”“×32 停不下来”），丰富档下还会震一下、连击数放大、每条轨道溅一圈碎片。连了 8 个以上断掉，横幅说一句“连击断在 N”。克制档：只换颜色，横幅淡入淡出，不震、不放大、没有碎片。
- **结算仪式**：星星一颗一颗砸下来（一颗一声）、准确率从 0 滚上去、过了关撒彩带；教练的脸在卡片上说一句（按这一局的数据挑的，不问 AI；三星是高兴的脸，没过是打气的脸）；下面一行是这一局涨了多少经验、经验条涨上去，升级了写“升到 Lv N”，拿到徽章亮出来。克制档直接摆好，过关只响一声。
  - 这一局的经验、升级、徽章只在结算卡片上说一遍：记成绩的时候 `gamepanel.js` 按着 `store.hush()`，`main.js` 那几条全页面的提示条看到 `store.quiet` 就不出（导航栏上的等级圈照常涨）。别的地方想自己亮经验，也用这一对。
- **音游外面那层**（`gamepanel.js` 的 `mountGame`，样式在“音游外面那层”）：地方够宽（这一块自己的宽度 ≥ 800）就左右两栏，左边舞台，右边一栏从上到下是：分段（看示范 / 跟打 / 独奏）、开打之前的检查、真机的镜子、速度和模式、这一关练什么、最好成绩、提示。接着真机时最要紧的两样排在最上面。窄的时候叠成一列，镜子和提示排到舞台下面。课程里的音游用的是同一个东西。
  - `mountGame(容器, 谱面, { fill: true })` = 外面给了固定的高度，舞台把它占满（练习场用）；不传就是舞台按屏幕的高矮取一个高度（课程里用）。`aside` = 放进右边那一栏的东西。
- **音游旁边的镜子只看要用的那一块**：`device-panel.js` 的面板多了 `focus(控件, { pad, minW, aspect })`，只改取景、不改图。没准备好时镜子转过去看该按的那个键，准备好了看 Synth keys 那一片，蓝圈圈出这个谱面用到的键。别的页面要“只放大相关的那一块”也用它。
- **练习场**（`views/arcade.js`）：谱面卡片的封面就是它一圈的图案，一行一条轨道、一格一步，彩色的是要你打的，灰的是伴奏。封面右下角的圆键（44 像素）是**试听**：放两圈自己停，播放头跟着声音走，同一时间只放一个；卡片别的地方点下去是进去打。有鼠标、又是丰富档时，停在卡片上播放头会按这个谱面自己的速度扫一圈（只是装饰，没有它也不缺信息）。分组标题放大了并写着有几个；“96 BPM”的标签不再折行；卡片上写着难度和最好成绩。
- **打一个谱面的那一页**：不整页滚动。最上面一行是返回、谱面的名字、难度，剩下的高度都给上面说的两栏。1024 × 768 下舞台大约 580 × 470。
- 检查用的：地址加 `?freeze=第几拍` 把舞台停在打到一半的样子（拍数越大连击越长，能看到三档里程碑），加 `?result` 或 `?result=几颗星` 直接摆出结算卡片，都不真的打、不记成绩；`tools/shots.sh` 和 `tools/mac-check.sh` 各加了这几样。

- **学完一关的那张卡上多一行“+N 经验”**（`views/classroom.js`；N 是这一下总共涨的，当天第一次练习的 20 也在里面；没涨就不显示）。导航栏的等级圈照常涨一下。升级、拿徽章由全页面的提示条说（没有按 `store.hush()`）。
- **徽章“三线齐亮”**：乐理、节奏、效果三条线各学完一关。
- **地图上的小关**：第 1 章前 T1「四个一组」和 R1「跟稳」，第 2 章前 T5「高和低」和 T7「亮和暗」，第 3 章前 T10「三个音叠起来」。对应关系和挂的动作在 `public/js/classroom-minis.js`（首页 import 它，所以画之前一定执行过）；名字和分钟数从小课堂的清单里取，学没学过、几颗星每次画首页时现问进度。写了还没开放的关不会挂出来。小关随时能点，不参与“学完前一关才解锁”；“走过的路”照样从它们身上亮过去，学没学过看的是键帽上的灯和下面的星星。
- **地图的排法改了一处**（`views/home.js` 的 `plan()`）：一章要排两行时分得匀一点。挂了两个小关的第 1 章有 7 个点，一行最多 5 个，原来会排成 5 + 2（第二行两个点分在两头，中间空一大段路），现在是 4 + 3。平板的三个尺寸下只有第 1 章受影响。
- **「设置」里的“清空学习进度”**把 `classroom` 一起清掉（`store.resetProgress()`）。
- 检查用的：`tools/mac-check.sh` 的首页那几行多了 `minis` / `minis-done`，最后加了一段 `classroom xp …`（学完一关涨多少、首页小关亮没亮、再学一遍、三条线的徽章、旧进度补算、清空）；`tools/shots.sh` 放进去的进度里带了小课堂学过的关；`tools/xp-check.mjs` 多打印小课堂那一项。

**没做的、要知道的**

- 小课堂的完成卡还是它自己那一张；换成公共的全屏庆祝是第 3 期的事。
- 首页的“接着练”和教练的问候不会提小关，它们只认主线的下一节课。
- 地图上只挂了方案里点名的 5 关。节奏线、效果线别的关（比如第 1 章前再挂 R3）要不要挂、等后面的章节做出来效果线挂在哪，都没定；一章最多挂两个，再多那一章就太长了。
- 徽章从 12 个变成 13 个，1024 宽下还是一行，但右边只剩一个徽章的位置：再多加一两个就要折行了。
- 验证：`tools/mac-check.sh` 通过；两套配色、三个尺寸下首页截图看过，另外在 1024 和 1366 宽下把整张地图截下来看过（没有重叠、没有出界）。在虚拟机的浏览器里用真实进度的副本走过一遍：点地图上的小关进去、把一关真的走完（等级圈涨、完成卡上写着涨了多少、回首页那个小关亮了）、再走一遍（不涨）、到「设置」里清空（小关全灭、经验归零）、再连着走 9 关（徽章和升级的提示条都出来了）。动效和声音实际的观感照旧没法在开发时验证。

## 第 3 期做完之后的样子（2026-11-10）

**做了的**

- **课程页的外壳**（`lesson.js` 的 `lessonView`，样式在 `app.css` 的“课程播放器”）：不整页滚动。最上面一行是回路线图、课名和进度条（一格一步，到过的能点回去；格子画得细，能点到的范围是整行 44 像素高），最下面一行是“上一步 / 下一步”，这两行固定，中间是这一步。步骤分两种排法：
  - **要动手的**（动手、编程挑战、练习）：一屏放下，左右两栏，左边是机器或舞台，右边是“现在做什么”，各管各的滚动。
  - **往下读的**（讲解、小测，以及导览、找按键、自由创作）：中间这一块自己上下滚。
- **动手**：左边是机器（没接真机是模拟机，接了是镜像），**只取要按的那几个键所在的那一块**，每换一项镜头跟着转过去，键放大到手指点得中（1024 × 768 下旋钮约 65 像素）；解说条右边有个“看整台”。**现在该做的那一项是一个气泡**，贴在机器上面，尾巴指着要按的键（`device-panel.js` 的 `spot()` 量键在屏幕上的位置）。右边是这一步的说明和整张清单（做完的打勾，正在做的亮着），下面是提示和“我已经做了”。没摆机器的步骤只有右边这一栏。
  - 做完一项：一声、一小撮彩带、那个键上闪一下绿圈、教练的脸高兴一下。整步做完：气泡变绿说“做到了”，彩带多一些，“下一步”亮起来的时候蹦一下。
- **编程挑战**：左边是机器，取景到这几条轨道的旋钮和两排步进键（步进键约 55 像素）；右边从上到下是说明、目标（能听）、机器上现在编成的样子（和目标上下对着看，少了的是空心框、多出来的是红格）、“检查”、结果。编对了有一声和一把彩带。
- **练习（音游）**：就是第 2 期那两栏，把这一步剩下的高度占满；这一步的说明放进了右边那一栏。1024 × 768 下不用滚。
- **讲解**：正文在左边一栏，一行 36 个字上下；紧跟着正文的“小贴士 / 注意 / 一点乐理 / 用 DJ 的经验来理解”挪到右边当旁注；小部件和面板图占满整行。丰富档下一块一块依次出现。没有另外配图：课程内容不在改版范围里，现有的小部件就是图。
- **小测**：一次只摆一题，上面写着第几题。选项是一排键帽（A / B / C）：答对了变绿、一声、一小撮彩带、给出解释，出现“下一题”；答错了变红、抖一下、灰掉，下面说这一项为什么不对。全部答对才能继续。
- **过一节课**：丰富档是**全屏的庆祝**（`celebrate.js`）：星星一颗一颗砸下来，经验条涨上去，升级了、拿到徽章了一起亮出来，教练说一句，下面是“下一课”。它后面的页面上同时有一张完成页（星星、经验、带走的要点、下次可以玩什么）；克制档只有这张完成页加一声。记“学完”的时候按着 `store.hush()`，所以这一下的经验、升级、徽章不会再另外弹提示条。
- **升级**（不在过一节课那一下的）：丰富档全屏（`main.js` 听到 `levelup` 就调 `celebrateLevel`），克制档是一条提示条。音游结算时的升级只在结算卡片上说，不盖全屏，免得挡住“再来一次”。
- **教练在课程里主动出现**（`coach-nudge.js`）：从导航栏最下面那张脸旁边冒出一个气泡，过十几秒自己收。什么时候出来：动手的某一项 45 秒没动静；同一项连着做偏了三回；编程挑战自己点“检查”两回都没过；练习连着两局没过；小测一道题答错两回。话是写好的，不调 AI；气泡上有“问问教练”，点了才把问题替你问出去。音游打着的时候、全屏庆祝盖着的时候、教练的侧栏已经开着的时候不出来；同一件事一次只说一遍。
- 版式变了，几句带方位的话跟着改了：课文 `content/ch0.js` 里四句（“下面的模拟机”→“左边的”，“顶栏的「面板」页”→“左边导航栏的”），给 AI 教练的 `docs/coach-knowledge.md` 里说界面位置的五句（顶栏、音游的检查卡片和镜子在哪、动手步骤里机器和气泡在哪）。**以后写课文：机器在左边，说明和清单在右边。**
- 检查用的：地址加 `?finish`（直接摆出这节课的完成页和庆祝；会把课记成学完，正式服务 4747 上不认）、`?celebrate=level`、`?nudge`；`tools/shots.sh` 加了这几张图，`tools/mac-check.sh` 加了动手的两栏和气泡、教练的气泡、完成页和庆祝三条。

**平板横屏：这一期补上的，和还留着的**

| 要求 | 第 3 期 | 留给后面 |
|---|---|---|
| 要动手的页面一屏放下 | 动手、编程挑战、课程里的练习：1024 × 768 下不用滚，机器（或舞台）和“现在做什么”同时看得见 | 导览、找按键、自由创作这三种步骤（一共 4 个）还是往下滚，里面的面板是整台：和面板页一起，第 4 期 |

**没做的、要知道的**

- 气泡是贴在机器**上面**、尾巴对准键的左右位置，不是紧挨在键旁边：紧挨着会盖住旁边的键，模拟机上就点不到了。

- 课程里嵌的小部件（节拍器、步进编辑、琴键……）没改版式，宽的讲解页上它们占满整行。
- 接着真机的情况只在假真机上走过；真的 iPad、真的机器上，动效、声音、键的大小合不合手，都还没有人试过。

## 第 4 期做完之后的样子（2026-11-10）

四期到这里都做过一遍了。下面是这一期做的，和整个改版做完之后还留着的事。

**做了的**

- **面板页**（`views/panel.js`、`panel-widgets.js`）：不整页滚动，标题和五个标签（真机镜像 / 模拟机 / 导览 / 找按键 / 灯色速查）在一行。地址带 `?tab=tour` 这样的参数可以直接打开某一个标签。
  - **模拟机**：左右两栏。左边的机器**一次只看一块**（鼓区 / 合成器区 / 音色与效果，上面一排开关切，也可以看整台），1024 × 768 下步进键约 50 像素，手指点得中；右边是按键百科，点哪儿讲哪儿。
  - **真机镜像**：左边是镜子，镜头跟着“照着试一遍”里下一步要按的键走，都做完了看回整台；右边是清单、机器现在的样子、刚才发生了什么。（**2026-11-11 用户改了**：一打开看整台，按了哪一块才转到哪一块，见“用户逐项验证的记录”第 8 项）
  - **导览**：左边机器，镜头跟着每一站讲的那一块走；右边是这一站讲什么和“上一站 / 下一站”，进度是一格一站、能点。
  - **找按键**：整台面板占满整行。这里没有放大：题目就是“在整台机器上把它找出来”，放大了等于把答案告诉你。
- **课程里的导览和自由创作**也成了一屏的左右两栏（用的是同一套组件）；找按键还是往下读的版式。到这里，课程里所有要动手的步骤都是一屏。
- 取景的那几样（只看一块、看整台的开关、跟着栏的高矮取景、大小变了重新取景）从 `lesson.js` 搬到了 `bench-view.js`，课程和面板页共用。取景时会把左侧那一列键旁边印的字一起框进来。
- **曲目**（`views/songs.js`）：每首歌一张带**封面**的卡片。封面是一块深色的小屏幕上一排音柱，高矮按歌名算出来（每首不一样、每次打开都一样），颜色跟着风格，四种风格四种排法；选中的歌音柱跟着节拍动。标签从每张五到七个减到零：速度写在封面上，难度是几颗点，“主要练什么”合成一行字。页面不整页滚动，最下面一行（选了几首、请教练排顺序）固定。“还想学别的”的输入框跑到内容区外面的问题修了。
- **设备**（`views/device.js`）：日常用的在上面：连接状态和机器的读数（排成两列）、遥控、延迟校准。排查问题才用的（按键体检、功能键测试、MIDI 监视器）收在最下面一个折叠里，默认不展开。“遥控”卡片被校准卡片拉高的问题修了：延迟校准平时只是一张小卡片，点“开始校准”才把舞台摆出来；它的说明也不再只说“按键盘 J”。
- **设置**（`views/settings.js`）：日常会动的在上面：界面（配色、动效、界面音效）、练习的两个开关。不常动的收在两个折叠里：教练背后的两个引擎（折叠着也看得到各自就绪没有；一个都没配好的时候它自己展开）、清空学习进度。
- 折叠用的是浏览器自带的 `<details class="fold">`，标题那一行 54 像素高。地址带 `?unfold` 时全部展开（截图用）。
- 给手指用的零碎：教练侧栏里“即时 / 深度”的开关加高；课文里能点的步进格子放得下就做到 44 像素高；导览进度格能点的范围加高。
- **屏幕键盘**：输入框拿着焦点、屏幕键盘把页面挡住一截的时候，整个应用缩到键盘上面看得见的那一块里（`main.js` 把高度写到 `--app-h`），教练侧栏的输入框不会被挡住。这一条没法在开发时验证，要在真的 iPad 上看。

## 用户逐项验证的记录（2026-11-10 起）

四期做完之后，用户让“一项一项问他、告诉他怎么验证”。一共 19 项，分三段。问过的记在这里：结果、他定下来的事、据此改了什么。**没问到的仍然算“做的人定的、没确认过”。**接着问的时候从第一条“还没问”的开始。

| # | 在哪试 | 验证什么 | 结果 |
|---|---|---|---|
| 1 | Mac，不接机器 | 首页的等级、经验、徽章和进度文件对不对；经验涨得快慢 | **对**（Lv 1 学徒、94 经验、3 个徽章）。快慢他“无所谓”，规则不改 |
| 2 | 同上 | 两套配色切换、动效两档、界面音效 | 切换正常、刷新后记得；按钮的声音可以。**他觉得霓虹“发光的感觉不明显”，当天加亮了（见下面），他再看过之后说“够了”** |

**拎起来玩**（同一天他接着要的：“鼠标可以拖动啾啾挪动到任一地方，随意把玩，啾啾可以做出各种反应”，`jiu.js` 的“拎起来玩”一段）：

- 按住它拖：吓一跳（“咦”的一声），扑腾着翅膀、腿悬着，跟着手走，朝着拖的方向；拎着走一秒半以上不晃，高兴起来（坐飞机）。拎着的时候身下有一团影子，鼠标是抓手。音游打着的时候拎不起来；它悬停指键时，按在它身上、身后正好是键的，那一下还是转给键（不拎它）。
- 松手就站在那儿（这一页上一直待着；换页、双击它、点开它选“回窝吧”、或者把它拖回窝，就回去）。站下以后随口说一句（“这儿视野不错，啾～”“新地方，啾！”……），理理羽毛或者跳一下。
- 站在机器图的某个键上：啄一下，“踩在 KICK 旋钮 上啦，啾！”，可以点“讲讲它”（就是“这个键是干嘛的？”那一套）。
- 拖到屏幕最上沿：“好高，啾！有点怕。”；拎着坐了一会儿飞机：“坐飞机咯，啾～”。

### 样板：《Faded》（2026-11-11 换的；他听了说“还可以”，加了混响之后说“够了”）

先做的样板是《Clint Eastwood》（D♯ PHRYGIAN、84 BPM、两小节），他说没听过这首，没法判断像不像，分轨数据已经删了（做法和查到的依据记在共享笔记 `song-parts-notes.md`）。换成《Faded》：

- **为什么是它**：他听过；90 BPM 慢；四个和弦一小节一个、从头到尾不变，正好是 3.4 课的键 1 → 6 → 3 → 7；前奏的钢琴旋律一拍一个音，只用 5 个键。机器上用默认的 MINOR 音阶，只要把 KEY 换成 D♯。它的和弦要第 3 章的 CHORD，所以标的是“第 3 章后可以开始”、难度 1。
- **这一版的样子**：原调 **D♯ 小调**，MINOR、KEY D♯，90 BPM，不摇，**四小节一圈**，6 条轨道：

  | 轨道 | 层 | 乐句 | 机器上 |
  |---|---|---|---|
  | KICK | 鼓 | 第 1、3 拍（1 小节，重复） | KICK 类，低、闷 |
  | SNARE | 鼓 | 二、四拍 | 厚一点、带点尾巴 |
  | HAT 1 | 鼓 | 反拍，每拍后半拍一下 | 闭镲，短、轻 |
  | SYNTH 1 | 贝斯 | 根音一小节两下：D♯ → B → F♯ → C♯（键 1、6、3、7） | BASS，OCTAVE −2 |
  | SYNTH 2 | 和弦 | 一小节一个，铺满：键 1 → 6 → 3 → 7 | PAD，CHORD 弹法，OCTAVE −1 |
  | DX | 旋律 | 前奏的钢琴，一拍一个音：F♯ F♯ F♯ A♯ │ 高 D♯ ×3 C♯ │ A♯ ×4 │ F F F D♯（键 3 3 3 5 │ 1 1 1 7，那三个 1 高一个八度 │ 5 5 5 5 │ 2 2 2 1） | 钢琴或电钢琴，OCTAVE 0 |

- **依据**（当天查的）：Musicnotes 的正式乐谱标 E♭ 小调、90 BPM；synthesizednotes、piano-keyboard-guide 的简谱都是 D♯m – B – F♯ – C♯ 一小节一个、不变，前奏旋律就是上面那一段。**鼓和贝斯的每一下是照这类歌的常见写法写的，没有逐下核对。**
- **和原曲不一样的地方**（页面右边原样列着）：机器 CHORD 的四个和弦每个都多一个音（D♯m7、Bmaj7、F♯maj7、C♯7，原曲是三个音的），会更软一点；鼓没逐下核对，二、四拍原曲是拍手和军鼓叠着、这里只用军鼓（应用自带的拍手声太薄，试听里听不清），原曲前奏没有鼓、这里一开始就叠着；贝斯只弹根音，原曲 Drop 里还有跟着底鼓“喘气”的侧链压缩（第 7 章）；旋律是前奏那段钢琴，人声没做；Drop 那种又宽又亮的合成器用一个宽一点的铺底加混响代替，铺底跟着底鼓“喘气”没做；试听里的混响和音色只是接近机器上的。
- 各层的音量在预览里量过，加了混响之后又量了一次（见下面“试听加上混响和延迟”）。

### 试听加上混响和延迟、换厚一点的音色（2026-11-11）

他听了《Faded》说“还可以，但氛围感不够强，是不是旋律以及和弦的音色问题，这个最后能通过采样来解决吗？”我答：主要是试听本身——应用自己的简易合成器、**没有混响**；机器上靠预置音色 + 发送效果（混响、延迟）能补回大半，采样适合补人声这类合成不出来的（第 5 章），旋律和和弦本身还是用合成器轨弹。问他要不要先让试听更接近机器上的样子，他说“好，先加上”。做了：

- **混响和延迟照机器上的“发送效果”做**（操作参考 3.12.1）：全机只有一个混响、一个延迟，每条分轨各自决定往里送多少。分轨上多了 `send: { reverb, delay }`（0–1，机器上是 Sound Design 第 3 页的旋钮 1、2），一首歌上可以写 `space: { reverb: 混响几秒, delay: 延迟隔几拍, feedback }`。混响是代码里生成的一段左右不同的衰减噪声（卷积），延迟的回授里过一个低通、出来再带一点进混响。都在 `song-player.js`；每首歌每条轨道的线只建一次。
- **两种新音色**（`audio.js`）：`wide`（五把错开音高、分散在左右的锯齿波，再垫一把低八度，起音慢、尾巴长）、`piano`（一下敲出来很亮，然后慢慢变暗变轻）。为了 `wide` 的左右散开，音色表里的每一把振荡器可以写 `pan`；没写 `pan` 的老音色声音不变。
- **《Faded》**：铺底换成 `wide`、混响送多、延迟送一点；钢琴旋律换成 `piano`、混响送多、延迟送一些；军鼓送一些混响、镲送一点；底鼓和贝斯不送（低频泡在混响里会糊）。混响 3.2 秒，延迟附点八分（0.75 拍）。分轨页每条轨道下面写着“混响送多、延迟送一点（Sound Design 第 3 页的旋钮 1、2）”，右边“机器上先这样设”多一行“空间”。
- 音量重新量过（每条独奏放半圈）：贝斯约 −18 dB、旋律 −19、底鼓 −21、铺底 −22（`wide` 几把锯齿波会互相抵掉一些，单听比 `pad` 轻得多，音色表里给得大）。
- 还是只是接近：机器上挑的预置音色、默认的混响类型会是另一种味道。铺底跟着底鼓“喘气”（侧链 / DUCKER）还没做。
- **他听了加混响之后的版本，说氛围感“够了”**（2026-11-11）。以后写别的歌，钢琴、铺底这类默认就送混响，底鼓、贝斯不送。

### 数据格式（`public/js/content/song-parts.js`）

按歌的 `id` 对上 `content/songs.js`，没写的歌就没有试听。一首歌：

- `bpm`、`swing`（机器上 [SWING] 的读数，ticks，−58 到 58；试听按 `swing / 120` 摇，和模拟机一样）、`scale`（`scales.js` 的第几个音阶）、`key`（0 = C … 3 = D♯）、`bars`（整首循环几小节）。
- `origKey`（原曲的调，说给人听的）、`summary`（一句话：这一版是怎么来的）、`differs`（和原曲不一样的地方，一条一句）。
- `parts`：按“照着搭”的先后排。每条有 `track`（`tracks.js` 的 id）、`layer`（drums / bass / chords / lead）、`role`（它在原曲里是哪一层）、`sound`（`{ cat: 音色类别, hint: 一句提示 }`）。
  - 鼓轨：`steps` 节奏串，写法同 `charts.js`（每小节 16 格，`x` 一下、`X` 重一点）；只写 1 小节就自己重复。
  - 合成器轨：`octave`（这条轨道的 OCTAVE）、`mode`（`mono` / `poly` / `chord`）、`voice`（试听用 `audio.js` 的哪种音色）、`notes: [第几步, 第几个 Synth key, 持续几步, 八度偏移?]`。音写成**键号**不写音名，因为学生在机器上按的就是键；实际的音由音阶、调、八度算出来（CHORD 用 `CHORD_PRESETS`）。八度偏移相对这条轨道的 OCTAVE，+1 = 这个音再高一个八度（Faded 的旋律用到），−1 = 再低一个八度。`vel` 可以不写，是试听时的力度（Pad 这种本身轻的音色要写大一点）。每条分轨还可以写 `send`（往混响、延迟里送多少），一首歌可以写 `space`（混响、延迟怎么设），见下面“试听加上混响和延迟”。

放音在 `public/js/song-player.js`：`SongPlayer` 把一首歌排成每一步的声音，交给循环播放器（`looper.js`）去放；`solo`（同一时间一条，和机器一样，独奏优先于静音）、`muted`、`only`（一层层加的时候现在响哪几条）。`audio.js` 为当初 Clint Eastwood 的口风琴旋律加了一种音色 `reed`（Faded 用不到，留着）。每种层的默认力度在 `song-player.js` 的 `VEL`，单首要调就在分轨上写 `vel`。

### “一轨一轨照着搭”的流程草案（2026-11-11 照它做成了课，见下一节）

一首歌一节课，从分轨页的“开始照着搭 →”进。课文尽量从分轨数据**自动生成**（任务的字、目标格子、核对条件都能从 `parts` 里算出来），每首只手写开场那几句和每层的一两句讲解。用的都是课程里现成的步骤类型（`read` / `do` / `program` / `game` / `free`），每一步在模拟机或真机上做。

1. **先听**（`read`）：嵌一个小的分轨台（就是这一页的放音），整首听一遍，再一层层加着听一遍。说清楚这是简化版、哪里和原曲不一样。
2. **准备工程**（`do`）：换到一个空工程；速度 90、Swing 归零、SCALE 第 1 个 MINOR、KEY D♯。**都能自动打勾**（`project` / `tempo` / `swing` / `scale`，真机和模拟机都认得）。这里顺带讲一句“KEY 换成 D♯，就能跟着原曲一起放”。
3. **鼓**（每条一个 `do` + 最后一个 `program`）：选轨、挑音色（`track`、`sound` 自动打勾），在步进键上填格子；三条填完用 `program` 核对位置（模拟机看格子，真机让机器放一圈录下来，都现成）。最后可以接一局 `game` 跟打鼓。
4. **贝斯**（SYNTH 1）：选轨、BASS 类音色、OCTAVE −2、[BAR LENGTH] 四小节（`track`、`sound`、`octave`、`length` 自动打勾）；第 1 小节填两下键 1，加长时机器会把它抄到后面三页，再一页一页把根音换成 6、3、7（按灭 → 按新键 → 按亮，3.4 课的做法）。`program` 核对位置和键号。
5. **和弦**（SYNTH 2）：PAD 类音色，**先挑音色再切 CHORD**（3.2 课讲过的坑：弹法存在音色里），OCTAVE −1，四小节，第 1 步放键 1 并拉满一小节，第 2–4 页用“按住步进键 + 按新键”换成 6、3、7（和 3.4 课同一个动作）。`polymode`、`length` 自动打勾，`program` 核对位置和键号。
6. **旋律**（DX）：钢琴一类音色、OCTAVE 0、四小节，一拍一个音填 16 个（每页 4 个，都落在第 1、5、9、13 个步进键上）。**第 2 小节那三个高 D♯**：先按 [OCTAVE] 升一格再按键 1，按完降回来——第 2 章没练过这个动作，课文里要单独一步。这一层最适合再接一局 `game` 跟着弹。
7. **合起来**（`do` + `free`）：用独奏、静音把四层拆开听一遍（`solo`、`mute` 自动打勾），再改一处自己的（换一个音色、去掉一层、改一下旋律），请阿拍点评；最后保存工程。

要补的小东西：
- **哪一步在哪儿核对**：位置（鼓、合成器）两边都能自动核对；键号模拟机能看，真机靠录下来的音符号换算（`program` 现在对键号只是“顺便看一眼”，要不要算过关再定）；**每个音在哪个八度**模拟机现在只认键号不认八度，要给模拟机和 `lesson.js` 加一种按音符号核对的条件；音长只有模拟机认得出。
- 课从哪儿挂：现在课都在 `curriculum.js` 的章节里，歌的课不属于哪一章，要给 `lesson.js` 加一种“歌的课”的来源（比如 `#/lesson/song-faded`），星和经验照普通的课算。
- 第 2 章后就能开始的歌，和弦、旋律两层要用第 3 章的 CHORD、改音长：要么这两层标“学完第 3 章再来”，要么在课里现教。

  - DX 的轨道色：褐色 → 玫红 → 现在是**青柠绿**（浅色 `#65a30d`、霓虹 `#b4f03c`；色环上 CLAP 的黄和 SYNTH 1 的绿中间那块空着，红、紫、粉那边都和别的轨道挨得太近）。只改了 `--t-DX` 一个变量，用到 DX 颜色的地方（分轨、完整版、首页地图的一块区域）一起变。
  - 完整版中间那张“段落 × 轨道”的表换成音频软件那样的时间线：最上面时间尺，段落按真实长短铺开（点一下从那里放），下面每 4 小节一个小节号；每条轨道一行（左边轨道名、独奏、静音那一列横着滚的时候钉住），每段乐句画成一个色块——鼓是一下下竖线（重音长一点），合成器按音高画小横条；色块左上角是第几段乐句（带 ↗ ↘ · 是滤波器怎么动）。一根播放头（红线 + 头上一个小三角，丰富档下跟着拍子跳）同时扫过所有轨道，每一步平滑滑过去；快走出看得见的地方时整条时间线横着跟过去。“跟着走”按钮可以关掉自动跟随，自己往前后翻。段落名和乐句编号在段落从左边看不见的地方开始时，贴着轨道名那一列钉住，不会被挡。
  - 一步 3 像素（一小节 48 像素），一首 2 分钟左右的歌时间线大约 3000 像素宽，1024 宽的屏幕上一次看得见 10 小节上下。
