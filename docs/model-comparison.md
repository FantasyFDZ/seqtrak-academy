# 教练用哪个模型：一次实测对比

日期：2026-11-10。工具：`tools/model-compare.mjs`（用的是和正式服务相同的人设、知识库与调用参数）。

**题目**：同一局练习——三轨 House 鼓组，120 BPM，准确率 58%，底鼓 15/16、拍手 7/8、反拍闭镲只中 5/16 且平均早 71ms——学生问“最该改进的一点、接下来怎么练、机器上怎么操作”。

**注意**：每个模型只跑了一次，耗时有波动（例如 `gpt-6-chat-thinking` 其它几次调用是 20–27 秒），结论只能当作方向性的参考。只比了“点评”，没有比“按弱点出题”。

## 深度点评（要求 250–400 字）

| 模型 | 通道 | 首字 | 总耗时 | 字数 | 观察 |
|---|---|---|---|---|---|
| `deepseek-chat` | DeepSeek API | 0.7 秒 | 4.3 秒 | 551 | 分析到位（“正拍有底鼓和拍手给你靠，反拍是空的”），操作全对；偏长 |
| `deepseek-flash` | DeepSeek API | 17.2 秒 | 18.5 秒 | 445 | 操作全对，“反拍要等不要追”；建议静音底鼓和拍手，对音游其实没用 |
| `gpt-5.6-sol` | Codex | — | 18.7 秒 | 425 | 操作全对，推断出“第 7 步四圈全漏”；最守格式 |
| `gpt-5.6-terra` | Codex | — | 19.6 秒 | 452 | 把开节拍器说成按住 [ALL] + [BPM-]（应为 [BPM+]） |
| `gpt-6-chat-thinking` | Codex | — | 40.6 秒 | 670 | 内容最细、操作全对，但超长近一倍，没按要求的格式 |
| `deepseek-v4-pro` | DeepSeek API | 93.5 秒 | 96.8 秒 | 432 | 唯一指出“音游速度在应用里调，机器不用动”的模型，质量最高；太慢 |

## 即时短答（要求 120 字以内）

| 模型 | 首字 | 总耗时 | 字数 | 观察 |
|---|---|---|---|---|
| `deepseek-chat` | 0.7 秒 | 2.1 秒 | 255 | 准确，操作全对；超长一倍 |
| `deepseek-flash` | 3.1 秒 | 4.0 秒 | 169 | 可用；列反拍时漏了第 15 步 |
| `deepseek-v4-pro` | 38.4 秒 | 39.5 秒 | 151 | 内容最准（给出了实时输入模式的正确进入方法）；不适合即时场景 |

## 追加（2026-11-10）：即时引擎换到自己的网关上的 `deepseek-flash-256k`

用户让把即时引擎接到 `../llm.env` 里那个自己部署的网关（`KNIGHT_AI_*` 那一组变量）上的 `deepseek-flash-256k`，估计“会更快”。在 Mac 上用正式服务同一套人设、知识库和调用方式（`fastStream`）实测，每格是两遍（长点评一遍）：

| 问什么 | `deepseek-chat`（DeepSeek 官方接口，原来的） | 网关 `deepseek-flash-256k`，照原样发 | 网关 `deepseek-flash-256k`，关掉思考 |
|---|---|---|---|
| 练习中随口一问 | 首字 0.4–0.7 秒，共 1.2–1.4 秒 | 首字 3.5 秒，共 3.7 秒 | 首字 0.6–0.7 秒，共 1.4–1.5 秒 |
| 点评这一局（短） | 首字 0.5–0.9 秒，共 1.4–1.6 秒 | 首字 1.2–1.6 秒，共 1.4–1.8 秒 | 首字 0.6–1.6 秒，共 1.2–2.1 秒 |
| 长点评（深度引擎那份提示词） | 首字 0.6 秒，共 2.6–3.8 秒 | 首字 8.0 秒，共 8.8 秒 | 首字 0.7 秒，共 3.4 秒 |
| JSON 模式（按弱点出题用） | 能用，4.9 秒 | — | 能用，3.7 秒 |

- **照原样发，它比原来慢**：这个模型默认先“思考”一段（流里先出 `reasoning`，一两百到六百个 token）再出正文，正文首字要等 1–8 秒。
- **关掉思考之后和原来一样快，没有更快**：首字都在半秒上下，偶尔一两秒；差别在每次的波动之内。只跑了两遍，结论只能当方向看。
- 关思考的参数试了 8 种写法，这个网关认两种：`thinking: {type: "disabled"}` 和 `reasoning_effort: "none"`（关掉后流里没有思考、用量里思考 0）；`enable_thinking: false`、`chat_template_kwargs`、`reasoning: {enabled: false}`、`reasoning_effort: minimal / low` 都不管用。
- 回答的内容：短答两边差不多，都对；长点评里网关这个出过一处小错（把一条轨道一共多少个音说少了）。

**现在的设置**：即时引擎 = 网关上的 `deepseek-flash-256k`，请求里带 `thinking: {type: "disabled"}`。服务商列表里多了一项“Knight AI 网关（DeepSeek 256K）”（`server/config.mjs` 的 `PRESET_DEFS.knight`，地址和 key 按变量名从 `../llm.env` 读，没有抄进项目；那个参数写在它的 `extra` 里，只对名字以 deepseek 开头的模型带）。换它的理由不是速度，是走自己的网关、不花 DeepSeek 按量的余额。**用户看了上面的数之后说“留着”（2026-11-10）。**想换回去：设置页“AI 引擎”里把服务商选回 DeepSeek 再保存。

## 结论与当前设置

- **即时引擎**：2026-11-10 起是网关上的 `deepseek-flash-256k`（见上面“追加”一节）。在那之前是 `deepseek-chat`：首字不到 1 秒，是当时唯一称得上“随问随答”的。它不太守字数，已在提示词里把长度要求写得更死。
- **深度引擎用 Codex 的 `gpt-5.6-sol`**：在 Codex 可用的模型里最快、没有出错、最守格式；走的是 Codex 的账号，不消耗 DeepSeek 的余额。
- `deepseek-chat` 只用 4 秒给出的长点评并不比 19 秒的 GPT 差。如果嫌深度点评等得久，把教练侧栏切到“即时”再问同样的问题即可。
- 两个带长思考的模型（`deepseek-v4-pro`、`gpt-6-chat-thinking`）内容更细，但等待时间不适合陪练。

## 环境备忘

- 这台 Mac 上有两个 Codex：Homebrew 的 0.137.0 和 npm 全局的 0.147.0。服务会自动选版本高的。
- Codex 配置里的默认模型 `gpt-6-astra` 要求比 0.147.0 更新的客户端，两个本地版本都用不了；`gpt-6.1-sol` 在 ChatGPT 账号下不支持。更新 Codex 之后可以把设置里的模型清空，回到自动选择。
- 默认不加载 `~/.codex/config.toml`（`--ignore-user-config`）：一句问候从 23–26 秒降到 9–11 秒，也避免把里面的 MCP 工具带进教练的调用。
- DeepSeek 的 key 从 `../llm.env` 的 `DEEPSEEK_API_KEY` 读取，没有复制进项目。接口当前列出的模型是 `deepseek-flash`、`deepseek-v4-pro`；`deepseek-chat` 作为别名仍可用。
